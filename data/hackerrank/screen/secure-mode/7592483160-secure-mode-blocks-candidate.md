# Secure Mode Blocks Candidate

_Last updated: September 3, 2026, 2:15 PM (Last updated 14 days ago)_

Secure Mode can restrict browser actions and access to other applications during a HackerRank for Work assessment. This article explains what to check when Secure Mode prevents a candidate from starting or continuing a test.

# Prerequisites

- Confirm that Secure Mode is enabled for the test.
- The candidate should use a supported browser and device.
- Verify whether the candidate sees an error message or a blocked-access notification.

# Troubleshooting Secure Mode

To troubleshoot a candidate blocked by Secure Mode:

1. Log in to your **HackerRank for Work** account using your credentials.
2. Navigate to **Tests** and open the affected test.
3. Review the test's **Settings** and confirm the Secure Mode configuration.
4. Ask the candidate to close applications or browser windows that may conflict with the secure assessment.
5. Ask the candidate to reopen the latest test invitation in a supported browser.
6. Verify that required browser permissions are allowed.
7. If the candidate is using a managed device, check whether organization policies restrict required browser functionality.
8. Ask the candidate to restart the browser and open the invitation again.

**Note:** Secure Mode may prevent access when browser, device, or organization policies do not meet the test requirements. Disabling unrelated browser extensions can also resolve conflicts.

If the candidate remains blocked, record the device, browser version, exact error message, and test name. See [📄 Candidate Cannot Start Test](/articles/2146387051) for general candidate access checks.
